# Setup

This project was tested using **Debian 13 with Cinnamon**.

## Prerequisites

Make sure the following tools are installed:

* **Docker 29.8.0**
  Installation guide: https://docs.docker.com/engine/install/

* **Pulumi v3.263.0**
  Installation guide: https://www.pulumi.com/docs/iac/get-started/kubernetes/begin/

* **Kind 0.30.0**
  Installation guide: https://kind.sigs.k8s.io/docs/user/quick-start/#installation

* **Go 1.27.1**
  Installation guide: https://go.dev/doc/install

* **OpenSSL**

The commands below assume that these tools are already available in your `PATH`.

---

# Building and Pushing the Image

Navigate to the `script` directory:

```bash
cd script
```

Make the CI script executable:

```bash
chmod +x ./ci.sh
```

Run the script with the image name:

```bash
./ci.sh <image-name>
```

The `<image-name>` should be the part that comes **before the `:tag`**.

For example, when using Docker Hub:

```bash
./ci.sh myusername/lab
```

The script will generate the image tag, run the unit tests, build the Docker image, and push it to the registry.

This setup assumes that you are already authenticated with the registry and have permission to push and pull images.

At the end of the script, the image name and generated tag will be displayed.

For example:

```text
Image: myusername/lab
Tag: abc123456789
```

# Optional: GitHub Actions CI

There is also a GitHub Actions workflow that can run the CI automatically.

A push to the `main` branch will trigger the workflow.

For this workflow, I chose **GitHub Container Registry (GHCR)** because it was more convenient for the project.

The workflow runs the tests, builds the Docker image, and pushes it to GHCR.

The resulting image name and tag are displayed at the end of the **Push Docker image** step of the workflow.

# Optional: Kubernetes Cluster

If you haven't created a Kind cluster yet, create one:

```bash
kind create cluster --name lab
```

You can use any cluster name you prefer.

Check the available Kubernetes contexts:

```bash
kubectl config get-contexts
```


The Kind cluster should appear in the list. Use its context name as the `kubeContext` value in `Pulumi.dev.yaml`.

For example:

```yaml
config:
  kubeContext: kind-lab
```

# Pulumi Configuration

Navigate to the infrastructure directory:

```bash
cd ../infrastructure
```

Open `Pulumi.dev.yaml` and update the values according to your environment.


The `image` and `tag` should match the image generated by the local CI script or the GitHub Actions workflow.

For example:

```yaml
config:
  kubeContext: kind-lab
  namespace: lab
  deploymentName: lab-deploy
  image: myusername/lab
  tag: abc123456789
  replicas: 1
  serviceName: lab-sv
  servicePort: 8080
  targetPort: 8080
```

# Deploy with Pulumi

Initialize the Pulumi stack:

```bash
pulumi stack init dev
```

Then deploy the infrastructure:

```bash
pulumi up
```

Pulumi will show you the resources that are going to be created and ask for confirmation before applying the changes.

After the deployment finishes, you can check the resources with:

```bash
kubectl get all -n <namespace>
```

For example:

```bash
kubectl get all -n lab
```

The application should now be running inside the Kind cluster.


To test the application you can set a port-forward to the service:

```bash
kubectl port-forward service/<svc> -n <namespace> <hostPort>:<servicePort>
```

For example:
```bash
kubectl port-forward service/lab-svc -n lab 8081:8081
```
